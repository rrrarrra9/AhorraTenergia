## 3. Metodología de trabajo

Utilizaremos GitHub Issues, GitHub Projects y Pull Requests para organizar el trabajo.

El tablero Kanban tendrá cinco estados:

1. **Backlog:** tareas identificadas pendientes de planificación.
2. **Por hacer:** tareas seleccionadas y listas para comenzar.
3. **En curso:** tareas que se están desarrollando.
4. **En revisión:** tareas pendientes de comprobación.
5. **Hecho:** tareas finalizadas y verificadas.

Cada integrante será responsable de mantener actualizado el estado de sus tareas.

## 4. Definition of Done (DoD)

Una tarea se considerará terminada únicamente cuando cumpla los siguientes criterios:

- [ ] El Issue tiene descripción, responsable, etiqueta y Milestone correspondiente, cuando proceda.
- [ ] Se han cumplido todos sus criterios de aceptación.
- [ ] El código o documento está correctamente organizado en el repositorio.
- [ ] Los cambios relevantes se han realizado en una rama independiente.
- [ ] Se ha creado una Pull Request vinculada al trabajo cuando corresponda.
- [ ] Otro integrante ha revisado y aprobado los cambios relevantes antes de fusionarlos.
- [ ] El código compila y supera las pruebas aplicables; los documentos han sido revisados.
- [ ] No se han publicado contraseñas, tokens ni información sensible.
- [ ] La documentación afectada está actualizada.
- [ ] Se han registrado las evidencias necesarias: commits, PR, capturas o pruebas.
- [ ] Los cambios se han integrado correctamente en `main`.
- [ ] El Issue y el tablero Kanban reflejan el estado final de la tarea.

La creación de un archivo o un commit no implica automáticamente que una tarea esté terminada.

## 5. Acuerdos de colaboración

- Todos los integrantes realizarán aportaciones propias al repositorio durante cada sprint.
- Las tareas se distribuirán de acuerdo con las capacidades y disponibilidad del equipo.
- Las decisiones importantes se documentarán.
- Los bloqueos se comunicarán durante las reuniones de seguimiento.
- Se priorizará el cumplimiento de los objetivos de cada sprint.
- El prototipo inicial será una simulación, sin realizar operaciones sobre una instalación eléctrica doméstica real.

## 6. Revisión de los roles y criterios

La distribución de responsabilidades y la Definition of Done se revisarán en las retrospectivas y podrán adaptarse a las necesidades del proyecto.
