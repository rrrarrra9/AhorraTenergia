\chapter{Introducción, problema y objetivos}
\section{Introducción}
AhorraTenergia es un proyecto intermodular orientado al desarrollo de un prototipo de gestión energética doméstica. Su propósito es reunir información sobre consumo eléctrico, producción solar, batería y precio de la electricidad en una solución que permita visualizar y simular decisiones de gestión. La primera versión utilizará datos simulados y no actuará sobre instalaciones reales.
\section{Problema o necesidad detectada}
En una vivienda con paneles solares, batería y conexión a la red, la producción y el consumo cambian durante el día. También varía el precio de la electricidad. Sin una vista conjunta resulta difícil comprender cuándo se consume energía solar, cuándo se recurre a la red y qué efecto podrían tener determinadas reglas de gestión. El prototipo permite estudiar estas relaciones sin ejecutar maniobras eléctricas reales.
\section{Usuario objetivo}
El usuario principal es una persona que quiere entender mejor el consumo de su vivienda, especialmente si dispone de autoconsumo fotovoltaico y eventualmente de batería. Como uso secundario, el proyecto demuestra la integración entre software, datos y electrónica en un entorno educativo.
\section{Propuesta de valor}
Centralizar las variables energéticas principales y simular cómo el precio, la producción y el nivel de batería intervienen en decisiones de gestión comprensibles para el usuario.
\section{Objetivo general}
Diseñar, desarrollar y demostrar un prototipo que visualice y simule la relación entre producción solar, consumo, batería y red eléctrica, incorporando el precio de la electricidad y centralizando la lógica de decisión en un backend.
\section{Objetivos específicos}
\begin{enumerate}
\item Definir una arquitectura que integre ASP.NET Core, React, Android Java, Supabase y ESP32.
\item Generar o recibir datos simulados de producción, consumo y batería.
\item Diseñar una API para recibir, validar y consultar información.
\item Almacenar medidas y un histórico de decisiones.
\item Proponer reglas simuladas de decisión basadas en precio y batería.
\item Diseñar interfaces web y móvil para visualizar el estado del sistema.
\item Comprobar el intercambio de datos y órdenes simuladas con ESP32.
\item Planificar pruebas de coherencia, comunicación y documentación.
\end{enumerate}
\section{Objetivo y alcance del Sprint 1}
Poner en marcha el proyecto: repositorio operativo, organización del equipo, backlog visible, arquitectura inicial y capítulo 1 de la memoria LaTeX. No se exige implementar todas las funcionalidades del MVP durante este sprint. Los resultados deben acreditarse mediante Issues, commits, Pull Requests, actas, capturas y documentos.
